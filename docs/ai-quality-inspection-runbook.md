# GEOFlow AI 质检运行手册

## 功能边界

AI 质检用于待发布文章的知识一致性、数据与引文、广告合规风险和内容完整性检查。系统输出风险提示与修改建议，最终法律判断由具备相应权限和专业能力的人员完成。

默认策略：

- 新任务默认关闭 AI 质检。
- 自动通过分为 85，人工放行最低分为 70。
- 0 至 69 分或存在 critical 问题时强制阻断。
- 70 至 84 分或证据覆盖不足时进入人工复核。
- 模型调用失败、输出结构无效或结果过期时保持草稿并暂停发布。

## 上线前检查

1. 在 AI 配置器中确认至少一个启用的对话模型可以完成结构化输出或 JSON 回退。
2. 确认系统方案 `article_quality.cn_ads_knowledge.v1` 已存在。
3. 确认任务至少关联一个知识库，知识切片已经完成，并根据业务要求完成资料审核。
4. 确认 `geoflow` 队列 Worker 和 Laravel 调度器持续运行。
5. 执行数据库迁移、配置缓存刷新和 Worker 重启。

```bash
php artisan migrate --force
php artisan optimize:clear
php artisan config:cache
php artisan queue:restart
php artisan geoflow:reconcile-ai-quality
```

## 运行链路

```text
文章生成或关联任务
  -> 保存草稿
  -> 现有确定性风险扫描
  -> geoflow 队列执行 AI 质检
  -> 后端校验引用、定位问题并计算分数
  -> 通过后回到原审核与发布周期
  -> 待复核、阻断、异常或过期时保持草稿
```

发布、分发、托管站点分配、人工发布和浏览器运营领取均调用同一组合门禁。缺少有效质检结果时会自动排队，并返回稳定的待处理或阻断错误。

## 单篇手动质检

文章编辑页的 AI 质检卡片支持“一键 AI 质检”和“重新 AI 质检”。任务没有开启 AI 质检时，点击“一键 AI 质检”只会为当前文章启用质检，任务设置保持关闭。系统沿用任务关联的知识库和阈值，提示词优先使用任务方案，未配置时使用系统默认方案；模型优先使用任务模型，缺少可用任务模型时使用当前启用的对话模型。

首次提交时，系统先保存编辑页里的当前内容，再为文章保存质检策略快照并排队执行。文章后续改动仍需重新质检，连续点击会复用排队中或运行中的记录。缺少知识库、质检提示词或可用模型时，页面会显示明确提示，质检历史和任务配置会继续保留。

已发布或私有文章在正文未变化时保持当前状态并排队复检。正文发生变化时，文章先进入草稿和待审核状态，系统记录用户请求的目标状态，质检通过后安全恢复。其他未发布文章保持草稿和待审核状态，通过质检后回到原审核与发布周期。

## 环境参数

```dotenv
GEOFLOW_AI_QUALITY_REQUEST_TIMEOUT_SECONDS=180
GEOFLOW_AI_QUALITY_MAX_EVIDENCE=24
GEOFLOW_AI_QUALITY_MAX_EVIDENCE_CHARACTERS=12000
GEOFLOW_AI_QUALITY_MAX_FACT_RETRIEVALS=60
```

事实候选超过单篇检索预算时会保留在结果快照中并标记为未覆盖，文章进入人工复核。调高预算会增加知识检索和模型上下文成本。

## 状态排查

### 长时间处于排队中

1. 检查 Horizon 或队列 Worker 是否消费 `geoflow` 队列。
2. 检查 `jobs` 和 `failed_jobs` 中的 `ProcessArticleAiQualityJob`。
3. 检查所选模型状态、API 地址、密钥、额度和最大输出 Token。
4. 手动执行 `php artisan geoflow:reconcile-ai-quality --limit=100`。

### 结果为执行异常

1. 在文章详情查看安全化错误提示和最近质检记录。
2. 检查模型是否支持所需输出长度；系统会先尝试结构化输出，再尝试严格 JSON。
3. 检查提示词是否保留全部必需字段、白名单变量和输出 Schema。
4. 修复模型或提示词后点击“重新 AI 质检”。

### 分数较高仍进入人工复核

以下条件会强制人工复核：

- 重要事实的知识证据覆盖为部分或不足。
- 存在高重要度不确定事项。
- 推广语境无法确认且存在广告性问题。
- 原文位置、事实编号、知识证据编号或法规依据未通过后端校验。

### 规则或知识更新后结果过期

文章内容、任务质检配置、提示词、模型、知识库元数据、知识切片来源哈希、法规规则版本和算法版本均参与输入指纹。相关变化会把旧结果标记为过期，并通过事件触发或每五分钟的补偿任务重新排队。

## 人工放行

人工放行仅适用于 `needs_review` 且分数达到人工放行最低线的结果。管理员需要填写至少四个字符的核查依据。系统记录管理员、时间、原因和当前输入指纹。文章或质检依据变化后，放行记录随旧结果一起失效。`blocked` 结果需要修改文章并重新质检。

## 回滚

代码回滚前先暂停新增任务执行并排空正在运行的质检 Job。数据库迁移回滚会删除质检记录、分段记录和任务配置字段；操作前必须完成数据库备份。保留迁移时，关闭任务上的 AI 质检开关即可恢复原生成行为，历史记录继续用于审计。
